# OHORA Nail Intelligence v4 — STEP 4-C 구현

## 범위

STEP 3의 레이아웃, 전역 검색/기간 흐름, 6개 태그 차원, 정확한 슬라이드 연결, 4개 `pending-generation` 장식 슬롯을 유지했다. STEP 4-C에서는 실제 스냅샷 기반 Excel 다운로드와 검증된 Instagram 플랫폼 표시만 추가했다. 장식 이미지는 생성하거나 교체하지 않았다.

## Excel 다운로드 계약

`Excel Download`는 현재 화면의 전역 검색, Asia/Seoul 기간, 게시물 테이블 필터 및 정렬을 반영한 `.xlsx` 파일을 브라우저에서 생성한다. 게시물 체크박스 선택은 내보내기 범위에 영향을 주지 않는다. 모든 시트의 1~3행은 같은 필터 범위를 설명하고, 4행은 자동 필터가 적용된 컬럼 헤더다.

| 시트 | 행 단위 | 포함 내용 |
|---|---|---|
| 디자인 인사이트 | KPI/지표/조합별 1행 | 선택 범위의 게시물·디자인 슬라이드·고유 색상·분류 태그, 보고 참여율 산술 평균, 별도 가중 참여율, 빈도순 디자인 조합, 조합 도넛 분포 |
| 게시물 | 선택된 게시물 1건 | 게시물 ID, 서울 날짜/UTC 시각, 검증 플랫폼, permalink, 원문 캡션, 게시물 디자인 판정, likes/comments/followers/보고 참여율, 원본 이미지 수, AI 슬라이드 수 |
| 이미지 | 선택된 AI 슬라이드 1장 | 게시물 ID, 원래 슬라이드 인덱스, 정확히 연결된 asset ID/URL, 매칭 상태, 슬라이드 디자인 판정, 6개 태그, 제한된 visual evidence |
| 캐러셀 | 선택된 캐러셀 게시물 1건 | 원본 carousel/image 수, AI 슬라이드 수, 정확 매칭 수, 원본 슬라이드 인덱스 순서, 해당 순서의 매칭 asset ID/상태 |
| 분석 품질 | 점검 항목 1건 | 현재 필터 범위의 행 수와 결측 건수, 참여율/조합 분모, 전역 원본 스냅샷 품질 요약 및 경고 |

이미지 시트는 원본 `image_assets` 100건이 아니라 AI 슬라이드 97건을 행으로 삼는다. 정확 매칭되지 않은 원본 자산 3건은 품질 시트에서 전역 건수로 알리고 해당 URL은 내보내지 않는다. 선택된 게시물의 AI 슬라이드 전체를 포함하며, 게시물/이미지 필터는 게시물 단위로 적용된다. 캐러셀 시트는 `isCarousel`, 원본 이미지 수, child 수 또는 AI 슬라이드 수가 여러 장임을 나타내는 선택 게시물만 담는다.

문자열은 Excel 수식으로 생성되지 않는 리터럴 셀로 기록한다. null 수치는 빈 셀로 둔다. 파일명은 선택된 게시물의 관측 날짜 범위를 사용하며, 결과가 없으면 `no-matching-posts`를 사용한다. 파일은 브라우저 다운로드 위치에만 생성한다.

## 플랫폼 표시

별도 플랫폼 필드가 없어 permalink에서 플랫폼을 판단한다. `https:` URL, `instagram.com` 또는 하위 도메인, `/p/`, `/reel/`, `/tv/`, `/stories/` 중 하나의 post route와 비어 있지 않은 route ID를 모두 확인한 경우에만 `Instagram`으로 표시한다. 호스트만 Instagram인 비정상 URL, 평문 HTTP, 유사 도메인, profile 경로는 플랫폼으로 표시하지 않는다. 현재 스냅샷은 24/24건이 이 검증을 통과했다.

## API 경계

개발 전용 allowlist에 내보내기에 필요한 슬라이드 `assetId`와 게시물 `isCarousel`, `imageCount`, `carouselChildCount`를 추가했다. 원본 응답 envelope, 미매칭 이미지 URL, API 인증정보는 노출하지 않는다. `/api/ohora-dashboard` GET만 사용하며 V4 개발 서버에서만 데이터를 읽는다. `E:\dashboard2`, n8n, DB, 인증정보에는 접근·수정하지 않았다.
